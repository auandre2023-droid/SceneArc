# 元資料備份與還原（離線）

這兩個 `.cmd` 檔可以直接按兩下執行，不需要 PowerShell，也不會連上網路。

| 檔案 | 用途 |
|---|---|
| `metadata-backup.cmd` | 把比對資料、設定與觀看進度複製到一個新的備份資料夾，並附上 SHA-256 雜湊清單 |
| `metadata-restore.cmd` | 核對備份完整之後，把它放回資料夾 |

## 會備份哪些檔案

| 來源 | 內容 |
|---|---|
| `host\build-mpv\data\anilist.json` | 作品比對、季資料設定、季鎖定 |
| `host\build-mpv\data\prefs.json` | 線上資料的設定（含 TMDB 金鑰） |
| `host\build-mpv\data\progress.json` | 觀看進度 |
| `host\build-mpv\data\lan_users.json`、`lan_progress\` | 區網使用者與各使用者的觀看進度 |
| `config.json`（專案根目錄） | 媒體庫與播放設定；在備份中放在 `app-root\config.json` |

不存在的檔案會略過，並在畫面上列出。縮圖、快取與記錄檔不在備份範圍內。

## 備份

1. 建議先關閉播放器。播放器開著時仍可以備份，但若剛好在寫入，畫面會提醒你再備份一次。
2. 按兩下 `tools\metadata-backup.cmd`。
3. 完成後畫面會顯示 `[完成] 已備份 N 個檔案，雜湊都已核對。` 以及備份位置。

備份位置：`%USERPROFILE%\Documents\VideoPlayer-metadata-backups\<日期-時間>\`，例如 `20261014-195243`。

每個備份資料夾裡有：
- 備份的檔案；
- `manifest-sha256.txt`：每個檔案的 SHA-256；
- `backup-info.txt`：來源路徑、時間與檔案數。

備份不會修改資料夾裡的任何檔案。

## 還原

1. **先關閉播放器。** 播放器（`VideoPlayer.exe`）在執行時，還原會拒絕進行，什麼都不會改變。
2. 把要還原的備份資料夾**拖到** `tools\metadata-restore.cmd` 上；或在命令列執行：
   ```
   tools\metadata-restore.cmd "%USERPROFILE%\Documents\VideoPlayer-metadata-backups\20261014-195243"
   ```
   不帶參數直接按兩下，會列出目前有哪些備份。
3. 還原會依序進行四個步驟：
   1. 核對備份中每個檔案的雜湊。只要有一個不符（檔案損壞或被修改），就拒絕還原，什麼都不會改變。
   2. 先把**目前**的檔案備份到 `pre-restore-<日期-時間>` 資料夾。這一步失敗也會拒絕還原。
   3. 把備份的檔案複製回去。
   4. 再核對一次寫入後的雜湊。
4. 看到 `[完成] 已還原 N 個檔案，雜湊全部相符。` 之後，再開啟播放器。

如果還原後想回到還原之前的狀態，用同樣的方法還原那個 `pre-restore-…` 資料夾即可。

**注意：**
- 只有備份裡有的檔案會被覆蓋；資料夾裡其他的檔案（例如備份之後新增的區網使用者進度檔）會保留。
- 還原的是整份 `anilist.json`，所以備份之後做的比對修改、季資料設定與季鎖定都會回到備份當時的狀態。

## 結束代碼（給自動化或排程使用）

| 程式 | 0 | 1 | 2 |
|---|---|---|---|
| `metadata-backup.cmd` | 完成並已核對 | 失敗 | — |
| `metadata-restore.cmd` | 已還原並已核對 | 拒絕或失敗 | 備份本身核對不符，什麼都沒有改變 |

## 其他資料夾

兩個程式都可以指定資料夾，用來處理其他安裝位置或資料副本：

```
metadata-backup.cmd  [資料夾] [config.json]
metadata-restore.cmd <備份資料夾> [資料夾] [config.json]
```

測試用的環境變數（平常不需要設定）：
- `VP_BACKUP_ROOT`：改變備份存放的位置；
- `VP_NO_PAUSE=1`：結束時不等待按鍵；
- `VP_EXE_NAME`：改變「執行中就拒絕還原」所檢查的程式名稱。

## 播放器自動保留的前三代（`.bak1`–`.bak3`）

除了上面手動的備份，播放器本身在覆寫 `anilist.json` 與 `prefs.json` 之前，會在**同一個資料夾**保留前幾代：

| 檔案 | 內容 |
|---|---|
| `anilist.json.bak1`、`prefs.json.bak1` | 最近一次輪替前的檔案（最新的一代） |
| `….bak2` | 再前一代 |
| `….bak3` | 最舊的一代；下次輪替時被取代 |

- **什麼時候輪替：** 每次啟動播放器後第一次存檔時輪替一次，之後同一次執行中最多每 30 分鐘一次。所以 `.bak1` 通常是「這次開啟播放器之前」的檔案，`.bak2`、`.bak3` 是更早幾次執行之前的檔案。（介面每次變動後都會存檔，若每次存檔都輪替，三代會只差幾秒。）
- **第一次寫入不會產生備份**（原本沒有檔案可以保留）。
- 只處理 `anilist.json` 與 `prefs.json`。`anilist_v2_backup*.json`、`prefs_v2_backup*.json` 這類一次性備份**永遠不會被輪替或刪除**；`progress.json` 不輪替（見下一節）。
- 不會複製資料：舊檔案只是換了名字（NTFS 上以硬連結完成，`anilist.json` 在任何時刻都存在）。在 FAT/exFAT 隨身碟上改用重新命名。

### 用 `.bak` 還原

1. **先關閉播放器。**
2. 開啟資料夾 `host\build-mpv\data\`（安裝版在安裝位置的 `data\`）。
3. 把目前的 `anilist.json` 改名為 `anilist.json.broken`（先留著，不要刪）。
4. **複製**（不要改名）想要的那一代，例如 `anilist.json.bak1`，貼上後把複本改名為 `anilist.json`。用複製可以讓 `.bak1`–`.bak3` 保持原樣，還原錯了還能再選另一代。
5. 開啟播放器，確認資料正確後，再刪掉 `anilist.json.broken`。

`prefs.json` 的步驟相同。若想先保險，可以在第 3 步之前先執行一次 `metadata-backup.cmd`。

## 播放器的其他資料保護（1B-b）

- **寫入一定完整：** 每次存檔先寫到 `<檔名>.tmp`，確定已寫進磁碟（`FlushFileBuffers`）之後才換名取代原檔。存檔途中當機或斷電，原檔仍是上一次完整的內容；資料夾裡可能留下一個 `.tmp`，可以忽略，下次存檔會覆寫它。
- **不寫入損壞的內容：** `anilist`、`prefs`、`progress` 存檔的內容若不是完整的 JSON 物件，播放器會拒絕寫入、保留原檔，並在 `data\logs\mpv-host.log` 記一行 `[data] saveData … refused`。
- **觀看進度讀不到時不覆寫：** `progress.json` 讀取失敗、是空檔或內容損壞時，播放器在這次執行中不會寫入觀看進度（記錄檔會有 `[data] progress.json is … progress is read-only`）。請用 `metadata-restore.cmd` 還原一份備份，或修好檔案，再重新開啟播放器。區網使用者的 `lan_progress\<使用者>.json` 也一樣：檔案損壞時不會被覆寫（記在 `data\logs\lan.log`）。
- **同一個資料夾只能開一個播放器：** 再開第二次時，第二個會把已開啟的視窗帶到前面後自行結束，不會讀寫任何資料。不同安裝位置（各自有自己的 `data\`）互不影響。

## 第五階段（身分圖，批次 A）與回滾

- **檔案格式版本不變：** `anilist.json` 仍是第 3 版（`"v":3`）。身分圖（作品、季與各資料庫 ID 之間的連結）每次都由比對紀錄重新算出，**不會存檔**。
- **只會多一個小區段 `graph`：** 只有在你第一次按候選旁的「不是這個」時，檔案最後才會多出 `"graph":{"v":1,"src":{},"gdec":{…},"checks":{}}`，裡面記錄你排除的候選（`gdec`）。從沒按過的檔案，存檔後與之前逐位元相同。
- **回到第四階段（`78cb5aa`）或第二階段（`912c067`）的程式：** 不需要任何轉換。舊程式會照常讀寫，並原樣保留 `graph` 區段（只是不再隱藏被排除的候選）。之後再回到第五階段，排除的紀錄仍然有效。
- **更早的備份：** 用 `metadata-restore.cmd` 還原第五階段之前的備份，`graph` 區段會隨之消失（等於從未排除任何候選），其他資料照常。
- **不需要新的工具：** 備份與還原只複製檔案並核對雜湊，與檔案內容的格式無關，所以 `metadata-backup.cmd`／`metadata-restore.cmd` 不變。部署前照舊先執行一次 `metadata-backup.cmd`。
- 程式內的 `downgradeStoreV2`（舊版回滾工具）預設保留 `graph` 區段；只有明確要求 `{graph:'drop'}` 時才移除（會失去排除紀錄）。第 4 版的轉換函式 `migrateStoreV4`／`downgradeStoreV3` 已寫好並經過來回測試，但**目前沒有任何地方呼叫**。

## 第五階段 批次 C（bangumi-data 資料集建議）：回滾與重建索引

- **資料集只提出建議：** 程式附帶一份只含本機媒體庫相關條目的 bangumi-data 索引（`ui\vendor\bangumi-data\index.json`，版本 0.3.231，CC BY 4.0；署名在「設定 → 線上資料 → 資料來源與授權」與同資料夾的 `ATTRIBUTION.txt`）。它只用你已經有的 AniList／MAL／Bangumi／TMDB ID 去找對應，從不用標題，也從不自己寫入連結或連網查詢。
- **部署後第一次啟動會寫入什麼：** 找得到建議的作品（以目前的正式資料是 23 筆），`anilist.json` 中該作品的 `review.candidates` 會多出「資料集建議」列（`"c":"dataset"`）。只有 `review` 改變，連結、季設定、鎖定與手動決定都不變；之後的啟動若沒有新建議就不再寫入。受保護的欄位與季（手動、季設定、鎖定、只用 TMDB、不使用線上資料）不會得到建議。
- **接受與「不是這個」：** 「接受」等同你在比對視窗親自選取：寫成手動連結，等主機確認存檔成功後，才向該資料庫查詢一次（存檔失敗時一切還原，也不查詢）；若該欄位或該季在建議產生之後已經有你自己的設定，接受會被拒絕並移除這個建議。「不是這個」記在 `graph.gdec`（與批次 A 相同）。第一次接受或排除時，`graph.src` 會記下 `"bangumi-data":{"ver":"0.3.231","sha256":…,"at":…}`。
- **回到 `398896c`、`78cb5aa` 或 `912c067` 的程式：** 不需要任何轉換。舊程式會原樣保留這些列；尚未比對的作品會把它們顯示成一般「候選」（可在比對視窗自行搜尋選取），已比對的作品一般不顯示（若該作品本來就列在待複查中，會一併列出，點選只會開啟比對視窗）。舊程式下一次為該作品做出比對決定時會清掉這些列，之後再回到批次 C，程式會重新提出仍然適用的建議。已接受的建議就是一般的手動連結，任何版本都照常使用。
- **重建索引（媒體庫加了新作品之後）：** 新作品要等它的 ID 進了索引才會有資料集建議。先讓播放器完成新作品的比對，然後雙擊 `tools\bangumi-data-index.cmd`：
  - 需要 Node.js，以及釘選版本的 bangumi-data `dist\data.json`（預設位置 `%LOCALAPPDATA%\Temp\jfr\bangumi-data\v0.3.231\data.json`，或把路徑當作第一個參數；SHA-256 不是 `da3ec080…974111b` 的檔案一律拒絕）。
  - 它先把 `host\build-mpv\data\anilist.json` 複製到暫存資料夾，只讀那份副本，然後改寫 `ui\vendor\bangumi-data\index.json`（同樣的輸入一定得到逐位元相同的檔案）。不連網、不改資料夾裡的任何檔案。
  - 完成後重新啟動播放器即可。要回到原本的索引，用 git 還原 `ui\vendor\bangumi-data\index.json` 就好；刪掉這個檔案，就不再產生新的建議（不會出錯，也不會連網；已寫入的建議列保留，仍可接受或排除）。
